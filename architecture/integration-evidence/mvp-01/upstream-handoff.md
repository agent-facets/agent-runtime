# Anthropic subscription code — ownership and provenance

**Decision (2026-09-30): the project owns a minimal internal derivative; no upstream release is required.** This
record keeps the planned `upstream-handoff.md` path, but no upstream delivery took place: the owner chose to stop
waiting for a public standalone contract from `@ex-machina/opencode-anthropic-auth` and approved a narrow
extraction instead (design Decision 10 as revised; tasks 9.4–9.5). It records what was decided and observed. It is
not G2 acceptance, which is recorded separately after the pre-console verification.

## What changed

The original plan made the runtime depend on an owner-supplied release of the plugin exposing injected login,
refresh and request adaptation, and blocked one step until it existed. Research on 2026-09-30 found that the
published v2 line (`next`) is an OpenCode v2 plugin with no such standalone entry. Rather than add that surface
upstream, the runtime now carries `packages/anthropic-subscription`: the auth and request-profile code it needs,
adapted to injected I/O, with everything OpenCode-specific left out. LangChain/LangGraph and the stock
`ChatAnthropic` remain the execution engine; no OpenCode host, plugin loader, framework fork or SDK fork is used.

## Extraction

Adapted, with each derived file citing its source: `auth.ts` (login URL, callback parsing, exchange and refresh
with bounded validation), `bounded.ts`, `pkce.ts`, `constants.ts` (as `oauth.ts` and `profile.ts`), `cch.ts` (as
`billing.ts`), part of `transform.ts` (headers, betas, `?beta=true`, identity and billing blocks; as `request.ts`)
and the recognition half of `version-rejection.ts` (as `response.ts`). Excluded: the plugin entry (`index.ts`:
hooks, connection tracking, alias leases, refresh caches, automatic version recovery, response replacement),
`json-response-stream.ts` and the tool-alias code (response rewriting), `rate-limit.ts` (429 body rewriting) and
`config.ts` (environment override).

The intentional differences D1–D9 — native tool names, delivery-aware auth outcomes, optional refresh rotation,
runtime token floor, version rejection classified not recovered, explicit immutable profiles, required leading user
text, subscription-only login with unchanged scopes, runtime-owned no-replay rule — are defined in
[PROVENANCE.md](../../../packages/anthropic-subscription/PROVENANCE.md). The owner approved D1–D5 and the
no-replay rule explicitly at task 9.4.

## Parity basis

Golden request fixtures for profile `claude-cli-2.1.280` were generated by running the upstream `dist` at the
recorded revision (from the verified tarball) over requests shaped like those the pinned `ChatAnthropic` sends;
the only change applied to upstream output is decoding its tool-name aliases back to the native names (D1). The
package's output matches those fixtures byte for byte, and upstream's own billing test vectors hold. This shows
agreement with the reference implementation; it is not evidence about what Anthropic's service accepts today, which
only the separately authorized live check can show. Native tool names were accepted live only under the older
2.1.87 profile (spike 03).

## Maintenance

The project maintains the derivative. There is no automatic synchronization and no npm tag is followed. An update
starts from an exact upstream version and revision: `bun run provenance:anthropic -- --version <v> --revision
<sha>` verifies the tarball and lists changed and new sources; wanted changes are ported by hand and recorded; a
changed request profile is a new profile ID, so paused runs keep theirs or are refused visibly; golden fixtures are
regenerated from upstream; and the offline gates are rerun. Editing the upstream repository is outside this
project's authority.

## Limitations

- Agreement with upstream is agreement with a reference, not with the service; live acceptance (G4) is separate and
  needs fresh owner authorization.
- The `org:create_api_key` scope is requested for consent parity; the runtime has no path that uses it.
- If the service rejects the reported client version, runs fail as an unsupported model/profile until a reviewed
  profile update ships.
