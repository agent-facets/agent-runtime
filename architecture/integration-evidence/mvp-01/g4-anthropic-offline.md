## Question

Under Bun, does the stock `ChatAnthropic` inside the stock agent send exactly the reviewed subscription profile —
headers, betas, `?beta=true`, identity and billing blocks, native tool names, the leading user text — through the
guarded terminal; replay tool results and a question's answer correctly; refuse truncated or error-terminated
streams before any partial message is stored; keep failures typed with their attempt; send nothing hidden; and do
the same through the production assembly on the official saver?

## Method

- **Golden parity** (`packages/anthropic-subscription/src/request.test.ts`): four requests shaped like the pinned
  model's output (captured from it with a local fake), adapted by the package and compared byte for byte with
  output generated by the upstream implementation at the recorded revision (only the D1 tool-name alias decoded).
  Upstream's own 2.1.87 billing vectors are checked as independent values.
- **Offline journey** (`packages/runtime/src/providers/anthropic/inference.test.ts`, 17 tests): the real agent, real
  terminal and hooks, real coordinator and store, and a fake network streaming Anthropic events one byte per chunk.
- **Production path** (`tests/integration/provider-assembly.integration.test.ts`, 7 tests, PostgreSQL): operator
  configuration → registry → stored binding → the assembly's wiring with durable admission → run controller →
  official saver; checkpoint tables scanned for tokens.

What the passing cases establish:

- **Wire profile.** Every request goes to `https://api.anthropic.com/v1/messages?beta=true` with bearer
  authorization, betas `oauth-2025-04-20,interleaved-thinking-2025-05-14`, user agent
  `claude-cli/2.1.280 (external, cli)`, no `x-api-key` and no browser-access header; system blocks are
  `[billing, identity, prompt]`; tools keep their native names. Adapting an adapted request changes nothing, so a
  renewal retry is not double-adapted. Requests the profile cannot represent (a history not opening with user text,
  non-native tool names, generated schema keys, other endpoints) are refused unsent.
- **Replay.** With one-byte chunking, a streamed `mcp_Read` call arrives whole, runs, and its result is replayed
  with the matching `tool_use_id`; the billing block is identical on every turn. A question pauses the run and its
  `false` answer is replayed as the tool result after verification against the stored binding.
- **Completeness.** A stream cut inside tool arguments, a text stream without `message_stop`, and one carrying an
  `error` event each fail the run as `incomplete_response` with its attempt, and the checkpoint holds no assistant
  message.
- **Failures and retries.** 429 (with `retry-after`), 529, 403 and a client-version rejection are classified with
  the real attempt reference (`rate_limited`, `provider_unavailable`, `authorization_rejected`,
  `model_unsupported`); a 500 is one request even when the invocation config asks for retries, while a control
  shows the stock model alone sends several. A 401 renews once and the retry is admitted and counted with the new
  generation; a 401 right after renewal fails the run and durably marks the slot, and a later run sends nothing. A
  renewal the issuer refuses is reported as authorization; one that never left as a temporary provider problem.
  Without authorization nothing is admitted or sent. Cancellation during a streaming response stops the run with
  nothing further sent.
- **Secrecy.** Checkpoints contain none of the synthetic tokens of any generation used, including across renewal
  and a response that echoes them.
- **Production wiring.** A changed default model leaves a paused run's stored binding in force; an unknown stored
  profile or the unregistered OpenAI binding is refused. Changing a subscription-package helper, the Anthropic
  adapter or its SDK changes Anthropic runs' definition; OpenAI-only changes do not.

## Findings

- The Anthropic SDK wraps errors thrown by its `fetch` (`APIConnectionError` with the terminal error as `cause`);
  without looking through `cause`, renewal failures and credential refusals lost their type. Found by the offline
  journey; fixed in the model boundary.
- The SDK turns an SSE `error` event into its own error before the stream ends; the terminal now ends such a
  stream with a typed `incomplete_response` as soon as the event is seen.
- `@langchain/anthropic` 1.5.11 reads `ANTHROPIC_API_URL`/`ANTHROPIC_BASE_URL` and, through `@langchain/core`, the
  LangSmith gateway when no endpoint is given. The factory always passes the endpoint, the terminal's exact-origin
  policy would refuse any other, and startup now refuses `LANGSMITH_GATEWAY`.
- One call-level retry on the stock model produced several physical requests (nested retry layers), which is why
  the boundary forces `maxRetries: 0` on every call.
